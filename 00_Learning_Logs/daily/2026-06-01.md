## 可复用经验

1. PoC 阶段纯 JSON 比 TS interface 更适合快速迭代——不需要编译工具链
2. JSON Schema 的 `description` + `example` 是重要自文档手段，未来 AI 生成时会直接引用
3. 校验脚本的枚举应从 schema.json 动态读取，避免两处维护导致不同步
4. Code Review 不只是审代码，schema/文档/约束同样适用 P0-P3 分级
5. **PoC 阶段「单 HTML 文件」模式**：零依赖，双击即运行，比搭 Vite+React 快 10x

## 今日思考题（可选）

1. 纯 JSON Schema 和 TypeScript interface 相比，哪个更适合 PoC 阶段？

   **纯 JSON Schema。** 原因：PoC 阶段不需要构建工具链，JSON 可直接被任何语言读取；schema.json 可同时作为校验器的数据源和未来 Player 的配置文档；TS interface 的编译检查和 IDE 提示在单文件 JSON 场景下收益不大。

2. 样例 JSON 的 workflowPhase 划分合理吗？如果教的是「事务」而不是 JOIN，步骤会怎么变？

   **合理。** 6 步覆盖了 SQL 执行完整链路。如果教「事务」，workflowType 应该改为 `concept-progression`，workflowPhase 会变成：concept（ACID 定义）→ transform（事务状态变化）→ compare（并发问题对比）→ summary（隔离级别总结），不再需要 lex/parse/plan 等 SQL 专用 phase。
