# Prompt: 需求澄清

## 使用场景

收到新功能需求、Bug 修复任务或重构请求时，将原始描述转化为结构化需求文档。

---

## 模板

```markdown
你是一个资深软件工程师，请帮我澄清以下需求。

## 原始需求

{{粘贴 issue / 口头描述 / 聊天记录}}
 给 ai_commit_review.py 接入 deepseek API，读取 git diff 生成 Code Review 报告

## 现有上下文（可选）


## 请输出

1. **需求摘要**（1-2 句话）
2. **用户故事**（As a ... I want ... So that ...）
3. **功能点清单**（编号列表，含优先级 P0/P1/P2）
4. **边界条件与异常场景**
5. **验收标准**（可测试的具体条件）
6. **不在范围内**（明确排除项）
7. **技术约束与依赖**
8. **待确认问题**（需要向 PM/用户确认的点）

## 要求

- 不要过度假设业务逻辑，不确定的地方列入「待确认问题」
- 验收标准必须可测试
- 如果需求模糊，先列出 3 个可能的理解方向
```
