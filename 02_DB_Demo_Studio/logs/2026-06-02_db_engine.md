## 我自己原本会怎么做

手工创建 Dockerfile，一个个容器起，手动写 SQL。连接器需要的时候现写。

## AI 帮我做了什么

1. **Docker 沙箱**：生成完整的 `docker-compose.yml`，MySQL 8 + PG 16 双容器含健康检查、端口映射（3307/5433）、持久化 volume
2. **初始化 SQL**：MySQL 版和 PG 版各一套，`students`（3 行）+ `courses`（4 行）表对齐 `join-query.json` 的样例数据
3. **统一连接器 `connector.py`**：Python 双引擎封装，支持 query / explain / 批量 EXPLAIN 对照
4. **基础设施**：`.env.example`、`README.md`、Kit 的 `requirements.txt` 追加数据库驱动

## 哪些地方有效

- **docker-compose 双容器设计**：一步启动，省去逐个配置的时间
- **connector.py 的 explain_both()**：一步完成 MySQL + PG 对照，架构文档要求的「双引擎 EXPLAIN」
- **SQL 数据对齐**：init.sql 的 3 名学生 + 4 门课程 JOIN 出 2 行结果，和 `examples/join-query.json` 的讲解词一致
- **统一端口映射**：MySQL 3307、PG 5433，与系统已有服务不冲突

## 哪些地方无效

- `connector.py` 依赖 `mysql-connector-python` 和 `psycopg2-binary`，需要额外安装。可以考虑将来用 SQLAlchemy 统一接口
- `.env` 文件本地需要手动 `copy .env.example .env` 才能用

## 我如何修正 AI 输出

- 规范了端口映射（MySQL 3307 / PG 5433 避免冲突）
- init.sql 外键约束加上 `ON DELETE` 策略
- connector.py 增加 `explain_both()` 工厂函数 + CLI 入口

## 可复用经验

1. Docker 沙箱 + connector 模式可以在 MCP Server 阶段直接复用
2. 双引擎 EXPLAIN 对比的接口设计可以沿用到 execution-workflow
3. 用 `healthcheck` 保证数据库就绪后才接受连接
